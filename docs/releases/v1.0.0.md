# PowerMap v1.0.0

Release date: 2026-08-17

## Highlights

- Access can now connect to multiple independently named remote peers. Each peer owns its
  credential, published targets, relay entries, relay tokens, and forced-relay setting.
- Port mappings, domain mappings, and reverse mappings bind to an immutable peer ID rather than
  the display name. Operators can rename a peer without changing where traffic goes, preventing
  cross-network routing mistakes.
- The Nodes workspace brings remote peers, local identity, per-peer relay settings, and reverse
  mapping ownership together. Remote credentials can be pasted as JSON while the local peer name
  remains mandatory.
- Loopback literal targets and hostnames that resolve to loopback require an explicit operator
  acknowledgement. NAT hairpin remains supported, without claiming automatic detection of every
  cross-machine loop condition.

## Compatibility

On first start, a v0.9.0 single access credential becomes one persistent peer named
`默认对端` (Default peer). Existing port and domain mappings are assigned to that peer by its
immutable ID. No mapping is silently rebound when a peer is renamed.

The root `[relay]` section remains the local expose Endpoint configuration. Access relay policy
is now stored per peer. For access-only legacy configurations with an explicit root relay policy,
the migration preserves that policy on the default peer.

Peers referenced by a port mapping, domain mapping, or enabled reverse mapping cannot be deleted.
Legacy global credential and relay endpoints report an ambiguity error when more than one peer is
configured, rather than selecting a peer implicitly.

## Upgrade

Use the in-console updater or install the matching release archive for your platform. Back up
`powermap.toml` and `powermap.key` before any downgrade: v0.9.0 does not understand the new
multi-peer access representation.
