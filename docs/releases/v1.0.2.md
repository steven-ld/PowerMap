# PowerMap v1.0.2

Release date: 2026-11-18

## Highlights

- The Nodes workspace now answers both directions of a connection. "Outbound nodes" lists the
  peers this machine connects to; a new "Inbound connections" list under the local node shows
  who is connected to this machine right now — the authenticated client, path and RTT, live and
  total tunnels, whether a reverse registration is active, and how many requests were denied.
  Entries disappear as soon as the connection closes, and a machine without the expose role
  says so instead of showing an ambiguous empty list.
- Each peer row now carries its own connection column: online state, direct or relayed path,
  round-trip latency, and how long the connection has been up. The dashboard adds a node strip
  that surfaces the same information at a glance, and configured peers that no mapping uses yet
  are labelled idle instead of raising a permanent disconnected warning.
- `/api/peers` and `/api/status` expose `path`, `rtt_ms`, `relay`, and `connected_since` per
  peer. Peer probing runs concurrently with a 500 ms cap per peer, so polling stays fast as the
  peer count grows, and the aggregate path field deterministically reports the lowest peer ID
  instead of changing every poll.
- Console interaction is more explicit: toggles, deletes, and saves mark the row "in progress",
  lock the buttons while the request is in flight, and flash the row once it settles. Reverse
  mapping shows a summary of the active policy plus an unsaved-changes hint, and the peer form
  folds published targets, dedicated relays, and forced relay into an advanced section.

## Compatibility

No configuration changes are required. The new fields and `/api/inbound` are additive; older
clients and consoles ignore them. The inbound list is populated by the expose role in the same
process, so a machine that runs only access reports `enabled: false` rather than listing nothing.

## Fixed

- The console's first-load bootstrap ran before a top-level constant was initialized, so the
  first `/api/peers` request always failed and peer state only appeared on the next poll.
- A failed inbound read now shows an explicit retry message instead of leaving "loading" on the
  page forever; already rendered rows are kept, since one failed request does not mean the
  connections are gone.
- Narrow-screen layouts keep the node and domain tables usable as labelled cards, and polling
  refreshes no longer steal keyboard focus from the row being operated on.

## Upgrade

Use the in-console updater or install the matching release archive for your platform. Docker
images are published as `ghcr.io/steven-ld/powermap:v1.0.2` and `:latest`; pin the version tag
in Compose. Downgrading to v1.0.1 only removes the new console views.
